# Glimpse

在主/副屏用置顶画中画低延迟预览另一块屏幕的轻量监看工具。适用于舞台表演投屏这类主副屏物理位置不在一起、需要边操作边确认输出的场景。

目标形态：同机零拷贝、跨设备局域网、点击穿透、全局快捷键。

## 当前状态

0.0.2 已完成 M1：WGC → 自有 D3D11 纹理 → DXGI 合成交换链 → DirectComposition 的 GPU 全显存链路，画面全程不经过 CPU 读回。验收标准为零丢弃与端到端 p95，而非固定帧率。

0.0.3 完成 M2：托盘（显示/隐藏预览、捕获源切换、基准测试、退出确认）、单实例激活、设置持久化（显示器设备名与窗口位置）、关闭窗口收进托盘、窗口内实时读数。点击穿透暂不可用，原因见开发文档风险清单。

M2.5 进行中：主控面板骨架（暗色自绘窗口、链路拓扑、五项实时读数与 60 秒延迟折线、视图切换）。选屏与输出控制、测试/诊断视图、异常态与首次引导待接入。

实测环境：Windows 11；主屏 2560×1440@180（Intel 核显，预览窗 446×792），副屏 1080×1920@60（NVIDIA，捕获源）。

| 指标 | 0.0.2 正向（主屏看副屏） | 0.0.2 反向（副屏看主屏） | 基线（CPU 路径） |
|---|---|---|---|
| 捕获 → 回调年龄 | p95 5–27 ms | p95 16–33 ms | — |
| 端到端延迟 | avg 7–20 ms，p95 18–38 ms | avg 15–24 ms，p95 28–42 ms | avg 26–42 ms，p95 39–57 ms |
| 呈现帧率 | 32–47 fps，跟随源变化帧 | 32–39 fps，跟随源变化帧 | 24–32 fps |
| 丢帧 | 0 | 0 | 约一半 |
| CPU | 约 0.16 个逻辑核 | 约 0.16 个逻辑核 | 约 1 个逻辑核 |
| 点击穿透 | 暂不可用 | 暂不可用 | 通过 |
| 捕获隐身 | 通过 | 通过 | 未实现 |

说明：WGC 显示器捕获按需出帧，静态画面不产生新帧，所以 `cap` 低于显示器刷新率是正常行为。用副屏全屏 60fps 自绘源做确定性测量，源实际重绘 57.2 fps，捕获 50.2 fps（44–56，p95 54），捕获率 87.8%，管线丢弃 1 帧；瓶颈在采集侧出帧，不在呈现管线。把帧池缓冲数从 2 增加到 3 做过四轮交替 A/B，差异被 ±10 个百分点的测量噪声淹没，因此保持 2。反向模式下源屏在核显、设备与预览在独显，WGC 需跨适配器出帧，延迟高于正向。

设备统一选择系统高性能适配器。按显示器选适配器在混合显卡机器上可能选到无法合成 DirectComposition 内容的核显，表现为预览窗全黑。

## 使用

启动后自动把第一块非主屏作为捕获源，在主屏右下角显示置顶预览窗。显示器序号见日志中的 `[显示器] #0/#1`。

反向使用（在副屏看主屏）：

```powershell
# 源码运行
dotnet run --project src/Glimpse -- --source 0 --preview 1

# 直接运行
src\Glimpse\bin\x64\Debug\net8.0-windows10.0.22621.0\Glimpse.exe --source 0 --preview 1
```

只指定一侧时，另一侧会自动选主屏或另一块屏。

- `Ctrl+Alt+Q`：退出；备选 `Ctrl+Shift+Q`
- 预览窗内部可拖动，边缘可缩放；缩放时按源画面宽高比锁定，画面始终填满窗口，不出现黑边
- 托盘右键：打开面板、显示/隐藏预览、切换捕获源、基准测试、打开日志目录、退出；双击托盘打开面板
- 主控面板：`Glimpse.exe --panel` 启动即打开，或从托盘打开；面板内可选捕获源与预览屏，同一块屏自动交换；可开关预览与窗口内读数、切换 25/50/75/100% 尺寸与右上/右下/居中/自由贴边；最小化到任务栏，关闭收进托盘，捕获与预览不中断
- 窗口层级：预览窗常驻最上层，切换其他应用时不会被盖住；主控面板不置顶
- 基准测试：托盘菜单运行 60 秒，或 `Glimpse.exe --benchmark 60` 无人值守运行后自动退出；面板测试视图可选 15 秒/60 秒/5 分并查看进度与逐项判定；报告写入日志目录
- 诊断日志：`%LOCALAPPDATA%\Glimpse\logs\glimpse.log`

当前限制：点击穿透暂不可用，DirectComposition 窗口无法在保留画面的同时让输入穿透，原因与解决方向见开发文档风险清单；HDR 源会先按 SDR 输出；面板的诊断视图与首次引导尚未接入；1 小时长稳留到 M2.5 面板完成后执行。
